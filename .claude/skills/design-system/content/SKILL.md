# Skill: Design System — UI Text & Labels

> ความยาวและถ้อยคำของข้อความใน component
> Parent: [design-system](../SKILL.md) · Sibling: [components](../components/SKILL.md) · [icons](../icons/SKILL.md) · [feedback](../feedback/SKILL.md)

---

## Trigger

Use this skill when:

- เขียน label ของปุ่ม / ตัวเลือก dropdown / หัวตาราง / tab / เมนู
- ตั้งข้อความ empty state, tooltip, toast, ข้อความยืนยันการลบ
- เห็น label ยาวจนตัดคำ ขึ้นบรรทัดใหม่ หรือทำให้คอลัมน์กว้างผิดปกติ

---

## หลักเดียวที่ต้องจำ

> **Use the shortest text that remains clear and unambiguous.**
> สั้นไม่ใช่เป้าหมาย — *ชัดเจนแล้วค่อยสั้น*

`Concise → Clear → Scannable → Front-loaded → บรรทัดเดียว`

---

## ความยาวที่แนะนำ (guideline ไม่ใช่ hard limit)

| Component | แนะนำ | เลี่ยง |
| --- | --- | --- |
| `Button` | 1–3 คำ | ประโยคยาว |
| `Select` option / `ActionMenu` item | 1–5 คำ | หลายบรรทัด |
| `FilterBar` label | 1–3 คำ | คำอธิบายใน label |
| `Tabs` | 1–2 คำ | เกิน 3–4 คำ |
| `Checkbox` / `Radio` | 1–6 คำ | ประโยคยาวถ้าไม่จำเป็น |
| `Field` / `Form.Item` label | 1–3 คำ | ยัด instruction ทั้งหมดลง label (ใช้ `hint` แทน) |
| `Tooltip` | 1 ประโยคสั้น | ย่อหน้า |
| Toast (`notify.*`) | 1–2 ประโยคสั้น | รายละเอียดยาว (ถ้าต้องยาว = ควรเป็น Dialog) |
| Table column `title` | 1–3 คำ | ยาวจนดันคอลัมน์กว้างเกิน |

ตัวเลขเป็นแนวทาง — `"ID"` กับ `"รายการที่ยังไม่ตรวจนับ"` กินพื้นที่ต่างกันมาก ให้ดูผลจริงบน layout

## Front-load — เอาคำที่ใช้แยกตัวเลือกไว้ข้างหน้า

ผู้ใช้ scan จากซ้าย ถ้าทุกตัวเลือกขึ้นต้นเหมือนกันจะต้องอ่านจบทั้งบรรทัดถึงจะแยกออก

```text
❌ ออเดอร์ที่ทำรายการสำเร็จแล้ว     ✅ สำเร็จแล้ว
   ออเดอร์ที่กำลังดำเนินการ            กำลังดำเนินการ
   ออเดอร์ที่ยกเลิก                    ยกเลิก
```

---

## Dropdown / Filter — ต้อง scan ได้เร็ว

```text
✅ สถานะ            ❌ แสดงรายการทั้งหมด
   ทั้งหมด              แสดงรายการที่กำลังใช้งานอยู่
   ใช้งาน               แสดงรายการที่รออนุมัติ
   รออนุมัติ            แสดงรายการที่ทำเสร็จแล้ว
   เสร็จสิ้น
   ยกเลิก
```

ถ้าจำเป็นต้องมีคำอธิบายจริงๆ **อย่ายัดลง dropdown** — เปลี่ยน component:
`Radio` พร้อมคำอธิบายใต้แต่ละตัว หรือ list ที่มี description

---

## อย่าตัดจนเสียความหมาย

```text
✅ ประวัติการทำรายการ      ชัด
✅ ประวัติ                 ใช้ได้ถ้า context ชัดอยู่แล้ว (อยู่ในหน้า Order อยู่แล้ว)
❌ ปวศ.                    สั้นเกินจนไม่รู้เรื่อง
```

หลักเดียวกันกับ filter: `สถานะการชำระเงิน` → ชัด · `สถานะ` → ใช้ได้ถ้ามีบริบท · `สถ.` → ไม่

## Destructive / confirm copy

- **หัวข้อต้องบอกว่ากำลังจะลบ *อะไร*** — `ลบสินค้านี้?` ดีกว่า `ยืนยัน?`
  ถ้ามีชื่อ record ให้ใส่: ``deleteTitle={`ลบหมวดหมู่ "${r.name}"?`}``
- **คำอธิบายบอกผลที่ย้อนไม่ได้** — `ไม่สามารถยกเลิกการดำเนินการนี้ได้` หรือระบุผลข้างเคียงจริง
  เช่น `สต็อกที่ตัดไปแล้วจะไม่ถูกคืนอัตโนมัติ`
- **ปุ่มยืนยันใช้คำกริยาของ action ไม่ใช่ "ตกลง"** — `ลบ` / `ยกเลิกบิล` เพื่อให้อ่านปุ่มอย่างเดียวก็รู้ว่ากำลังทำอะไร

---

## Don't

- ใส่ instruction ยาวใน `Field.label` — ใช้ `hint` (มันมี `aria-describedby` ผูกให้แล้ว)
- ให้ label ขึ้นบรรทัดที่สองใน `Tabs` / `Segmented` / `FilterBar` — ถ้ายาวไปแปลว่าเลือกคำผิด
- ใช้ตัวย่อที่ไม่ใช่คำมาตรฐานของธุรกิจ (SKU, PO ใช้ได้ — คำย่อที่คิดเองไม่ได้)
- เขียน toast เป็นย่อหน้า — ถ้าผู้ใช้ต้องอ่านนานแปลว่าต้องใช้ Dialog ([feedback](../feedback/SKILL.md))
